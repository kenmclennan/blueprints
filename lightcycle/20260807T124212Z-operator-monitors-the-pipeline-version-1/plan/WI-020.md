## WI-020: Footer: pool running indicator

**Brief:** Wire the footer's pool-running segment to WI-002's read-only use case, refreshed on the
existing 10-second poll loop.

### Acceptance Criteria

Copied verbatim from the source story:

- Given `lc start` is running, when I look at the footer, then it shows a clear 'pool running' indicator.
- Given `lc start` is not running, when I look at the footer, then it shows a clear 'pool not running'
  indicator, never blank.
- Given the pool's running state changes while the dashboard is open, when that happens, then the footer
  updates without a manual refresh.

### Source References

- **Artifact ID:** wireframes/wireframe-priority-list.html
- **Section:** `#normal` footer
- **Excerpt:** `<span class="pool">● pool running</span>` - left-aligned, first segment of the status
  line, styled with the `--cyan` token per `.footer .status .pool`.
- **Artifact ID:** architecture/tui-architecture.md
- **Section:** "Resolved decisions"
- **Excerpt:** "Poll interval: 10 seconds."

### Dependencies

- WI-010, WI-002 (read-only pool-running-state use case).

### Constraints

- Must never render blank - both running and not-running states have their own explicit indicator text
  per AC-2. The wireframe only shows the running state literally; the not-running indicator's exact
  wording is not specified anywhere in this design.
- Reuses the existing 10-second poll loop from WI-010 - no separate refresh mechanism.

### Verification

- Pilot test: fixture with the pool running shows the "pool running" indicator.
- Pilot test: fixture with the pool not running shows a distinct, non-blank indicator.
- Pilot test: simulating a running→not-running transition across two poll ticks updates the footer
  without requiring app restart or manual action.

### Open Questions

- `[builder]` Exact wording for the "pool not running" indicator - not specified by any wireframe state
  in this design (all shown states have the pool running).

### Deliverable

The footer's pool-running indicator is always present and correct, updating live via the poll loop.
