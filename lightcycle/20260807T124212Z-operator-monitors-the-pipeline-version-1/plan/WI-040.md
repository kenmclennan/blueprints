## WI-040: Select an artifact to open it + return without losing position

**Brief:** Standard list navigation (arrows + confirm) over the artifact list, dispatching to whichever
kind-appropriate viewer WI-041/042/043/044 build. Closing an opened artifact list returns to the hub view
it was opened from - bundled since a selectable list with no return path is not releasable.

### Acceptance Criteria

Copied verbatim from "Select an artifact to open it":

- Given the artifact list has more than one entry, when I press up/down, then the selection moves
  accordingly.
- Given an artifact is selected, when I confirm the selection with Enter or →, then it opens in the
  viewer appropriate for its type.

Copied verbatim from "Return to the node without losing position":

- Given I opened the artifact list from a node's hub view, when I close it with Esc or ←, then the hub
  view reappears as it was.

### Dependencies

- WI-039.

### Constraints

- This item's own dispatch logic is a pure hand-off by `kind` - it does not implement any viewer itself;
  WI-041/042/043/044 each own their own kind's rendering.

### Verification

- Pilot test: arrow keys move selection through a multi-artifact list.
- Pilot test: confirming a selection routes to the correct viewer stub/kind (verified fully once
  WI-041-044 land; this item's own test can assert the dispatch call, not the rendered viewer).
- Pilot test: closing the artifact list (opened via the ordinary hub → Artifacts tab path) returns to the
  hub as it was.

### Open Questions

- `[designer]` What closing the artifact list does when it was opened via the `a` shortcut directly from
  the Hierarchy tab (WI-037), bypassing the hub entirely - land in the node's hub, or return straight to
  the Hierarchy tab it was jumped from. Neither this story nor WI-037 settles it, and no principle
  resolves it either (One Navigation Contract states "always returns to exactly where you left off" but
  doesn't define what "where" means when there was no intermediate hub screen).

### Deliverable

The artifact list is fully navigable and dispatches correctly by kind; the ordinary hub-opened path
returns correctly on close.
