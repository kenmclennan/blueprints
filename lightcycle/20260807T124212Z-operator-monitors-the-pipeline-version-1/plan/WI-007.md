# WI-007 - Artifacts tab and artifact viewer

## What

The hub's Artifacts tab lists a node's viewable artifacts, and selecting one opens it - rendered in place, or handed off to the operating system, according to what kind of artifact it is.

## Defined by

- [wireframe-artifact-viewer.html](../wireframes/wireframe-artifact-viewer.md) - the authoritative layout for the viewer, per artifact kind, including which token this screen deliberately does not use.
- [wireframe-hub.html](../wireframes/wireframe-hub.md) - the Artifacts tab's own list rendering. It has no empty state; that message is specified in [See the artifacts attached to a node](../user-stories/da91328b-2935-4b00-8444-63bd41cf0263.md)'s acceptance criteria.
- [TUI Architecture](../architecture/tui-architecture.md) - the per-kind dispatch table for the viewer, the resolution order that decides an artifact's kind, which artifacts are excluded from this tab and why, and the cross-platform file-open decision.
- [Keyboard Navigation Scheme](../design-system/keyboard-navigation-scheme.md) - selection, opening, and back-navigation from both the tab and the viewer.
- [Screen Flow](../user-flows/screen-flow-current.md) - the transitions between the tab and the viewer.
- [Observation Only](../principles/observation-only.md) - why handing a file to another application is still within this design's read-only posture.

## In scope

- The Artifacts tab's list, filtered as the architecture specifies, and its empty state.
- The viewer for every kind the architecture's dispatch table names.
- The two hand-off kinds, including the cross-platform launcher.
- Back-navigation from the viewer to the list and from the list to the node, restoring position in both cases.
- The depth criterion of [Switch to the backlog with a tab or shortcut](../user-stories/5fa1445f-dc04-4322-b1be-e00496e8d0d9.md), for a jump made from this screen. WI-004 owns that story's other criteria.

## Out of scope

- The hub shell and tab cycling - WI-005.
- The Log tab - WI-006.

## Done when

The acceptance criteria on all eight stories hold, and every kind in the architecture's dispatch table renders or hands off.

## Notes from the codebase

The engine side is done and locked by a feature test. `Artifact` (`lightcycle/domain/work/artifact.py`) carries `internal` and `kind`, and `default_kind_for` implements the type-to-kind default table exactly as the architecture specifies, with unknown types falling back so rendering stays total. Filtering this tab is therefore reading `internal`, not inferring anything.

Where the design and the codebase disagree, the design wins.

## Open questions

- `[builder]` Whether the artifact-viewer's per-kind dispatch is a mapping or a widget hierarchy. The architecture names what each kind does; how the dispatch is structured is a build-time choice.
