## WI-037: Hierarchy: `a`/`l` shortcuts jump to Artifacts/Log

**Brief:** From a node highlighted (not opened) in the Hierarchy tab, `a` opens its Artifacts tab
directly and `l` opens its Log tab directly (live if active, past/historical if done), skipping whichever
tab WI-028's contextual-landing logic would otherwise default to. A no-op on `l` for a human step or a
step that hasn't run.

### Acceptance Criteria

Copied verbatim from the source story:

- Given a node is highlighted in the tree, when I press a, then its artifact list opens directly.
- Given a node is highlighted in the tree, when I press l, then its log opens directly - live if it's the
  active step, past/historical if it's done.
- Given the highlighted node is a human step or hasn't run yet, when I press l, then the shortcut is a
  no-op, consistent with there being no log content to show.

Added to close a gap found during this plan's own Pass 7 adversarial review (not part of the source
story - see Provenance in WI-055): a highlighted row can be a WI-055-projected planned step, which has no
real `Node`, so neither `a` nor `l` has anything to jump to.

- Given the highlighted node is a planned (not-yet-filed) step from WI-055's projection, when I press
  either a or l, then the shortcut is a no-op - there is no real node, so there are no artifacts and no
  log, a stronger case than "hasn't run yet" (which still names a real, queued `Node`).

### Dependencies

- WI-030, WI-029 (the tab set/switching mechanism these shortcuts jump directly into), WI-055 (planned
  rows, which both shortcuts must no-op on).

### Constraints

- This item wires the `a`/`l` keybindings and the direct-jump navigation only. The Artifacts and Log
  tabs' own real content is built in Milestone 3 (WI-039) and Milestone 4 (WI-045) respectively - until
  those land, this item's own verification uses whatever placeholder/empty tab body Milestone 2 has
  established, confirming the correct tab becomes active and the correct node opens.
- `l` must be a true no-op (nothing happens, no error, no partial navigation) for a human step or a step
  that hasn't run - not an error message or an empty log view.
- Both `a` and `l` must be a true no-op for a planned (not-yet-filed) row - checked before attempting to
  open anything, same discipline as WI-036's own handling of the same case.

### Verification

- Pilot test: pressing `a` on a highlighted node opens it with the Artifacts tab active.
- Pilot test: pressing `l` on a highlighted active step opens it with the Log tab active.
- Pilot test: pressing `l` on a highlighted human step or not-yet-run step does nothing observable (no
  navigation occurs).
- Pilot test: pressing `a` or `l` on a highlighted planned (not-yet-filed) row does nothing observable.

### Deliverable

`a` and `l` correctly jump a highlighted hierarchy node directly to its Artifacts or Log tab, with `l`
correctly a no-op where there's nothing to show.
