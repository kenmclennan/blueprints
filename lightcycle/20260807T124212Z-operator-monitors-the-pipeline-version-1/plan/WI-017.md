# WI-017 - Artifact Viewer header colour treatment and position indicator

## What

Filed by `audit-design` against the built Artifact Viewer, not by a story - two header-level gaps found by rendering the real composited screen and reading `hub.py` against `wireframe-artifact-viewer.html`, neither of them WI-008 or WI-010's already-delivered fixes.

## Reproduced

Both against `origin/main` at `13694fc` via `tests/support/tui_harness.py` reading the actual composited frame.

1. **The header colours the whole "type · id" string cyan, where the wireframe colours only the type word cyan and the id dim.** [wireframe-artifact-viewer.html](../wireframes/wireframe-artifact-viewer.html)'s header markup is `<span class="kind">findings</span> · LC-45`, where `.head` defaults to `--dim` and only `.head .kind` (the artifact's type word) is `--cyan` - the id portion is deliberately dim, the inverse of how the hub's own row-level id treatment works. `ArtifactViewerHeader.update()` (`hub.py`) instead renders the entire `"%s · %s" % (type, node_id)` string as one `Text(..., style=COLOURS["cyan"])`. `uv run python -m tests.support.screen_render artifact-viewer#text --colour` and `#list --colour` both show `findings · LC-45` end-to-end in `--cyan`, with no dim segment anywhere.
2. **The text-artifact viewer never shows the wireframe's "N / N" position indicator.** [wireframe-artifact-viewer.html](../wireframes/wireframe-artifact-viewer.html)'s text-artifact state header has a right-aligned `<span>1 / 1</span>` alongside `findings · LC-45` - part of the same per-kind header layout that already gives the list-kind its own right-aligned `"3 items"` segment correctly. `TextArtifactViewerScreen.on_mount` (`hub.py`) calls `ArtifactViewerHeader.update(kind_text, None)`, hard-coding `count_text` to `None` - there is no code path anywhere that supplies a position value to the text viewer's header. `uv run python -m tests.support.screen_render artifact-viewer#text --colour` shows the header line ending in blank padding, no `1 / 1` or any indicator, regardless of how many artifacts the node has.

Neither is covered by any existing scenario in `tests/feature/the-artifact-viewer.feature`.

## Defined by

- [wireframe-artifact-viewer.html](../wireframes/wireframe-artifact-viewer.html) - the `.head`/`.head .kind` colour rule (point 1) and the text-artifact state's right-aligned position indicator (point 2), both part of "the authoritative layout for the viewer, per artifact kind" WI-007 was defined by.
- [Design System Tokens](../design-system/design-system-tokens.md) - the colour token table (`--cyan` for active/selected/current state, `--dim` for secondary/muted text), which point 1 is checked against.

## In scope

- Splitting the artifact-viewer header so only the type word is `--cyan` and the id is `--dim`.
- Supplying the text viewer's header with a position indicator (`N / N`) matching the list viewer's existing pattern.

## Out of scope

- Anything already delivered by WI-008 (type-column overflow in the Artifacts tab's list) or WI-010 (footer status line on the viewer screens).
- The list viewer's own position/count segment, already correct.

## Done when

The artifact-viewer header colours only the type word `--cyan` with the id `--dim`, and the text-artifact viewer shows a position indicator matching the wireframe, both verified on the actual composited frame.
