## WI-051: Switch to the backlog with a tab or shortcut

**Brief:** A persistent tab strip switches between Current work and Backlog; `Tab` does the same from
anywhere, including from several screens deep (an open artifact, a live log) - bypassing the normal
one-level-at-a-time Esc/← back-stack entirely, landing straight on the sibling top-level view.

### Acceptance Criteria

Copied verbatim from the source story:

- Given I'm viewing current work, when I select the backlog tab or press its shortcut, then the backlog
  replaces the current view.
- Given I'm viewing the backlog, when I select the current-work tab or its shortcut, then I return to the
  priority list.
- Given I am several screens deep (e.g. viewing an artifact or a live log), when I press Tab, then I jump
  straight to whichever of current work or backlog I'm not currently in, from wherever I was.

### Dependencies

- WI-050, WI-025 (reuses the same priority-level-binding technique WI-025 established for `q`/Ctrl+C, so
  `Tab` resolves correctly regardless of which widget currently has focus at any depth).

### Constraints

- **Must use a priority-level binding**, matching WI-025's own reasoning exactly - a plain App-level
  binding would be shadowed by whatever widget has focus (the Hierarchy tree, live log view, artifact
  list), breaking AC-3's "from wherever I was" requirement.
- This is an explicit, deliberate exception to the One Navigation Contract's normal one-level-at-a-time
  Esc/← behavior - not an extension of it. Esc/← on the artifact viewer or live log still only returns
  one level.

### Verification

- Pilot test: pressing the tab strip or `Tab` from the Priority List switches to Backlog and back.
- Pilot test: pressing `Tab` from a deeply-nested screen (an open artifact, per WI-041; a live log, per
  WI-045) jumps straight to the sibling top-level screen, bypassing every intermediate Esc/← level.

### Deliverable

`Tab` and the tab strip reliably switch between Current work and Backlog from any screen and any depth.
