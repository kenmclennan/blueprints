## WI-027: Hub header: current step, role, elapsed

**Brief:** Add the STEP/ROLE/ELAPSED field group to the hub header, populated from the same role and
elapsed-time sources Milestone 0/1 already built.

### Acceptance Criteria

Copied verbatim from the source story:

- Given an item's detail view is open, when I look at it, then it names the current step.
- Given the current step is performed by a worker, when I look at the detail view, then it names the
  role (e.g. write-code, review-code).
- Given the item is active, when I look at the detail view, then it shows an approximate elapsed time,
  matching the list's format (e.g. '14m', '1h 7m').
- Given the current step is a human step with no worker, when I look at the detail view, then no role or
  elapsed time is shown for a worker that doesn't exist.

### Source References

- **Artifact ID:** user-stories/45d7d629-f736-4875-8470-f928558a88ea.md
- **Section:** Context
- **Excerpt:** "STEP and ROLE are two independent fields on the node (`role`, `step` in
  `lightcycle/domain/work/node.py`), not one derived from the other. The wireframe's Hierarchy tab shows
  this directly: sibling steps like `spec-open-pr` and `code-open-pr` both carry role 'open-pr', distinct
  from their own step id... The AC-4 case (human step, no role/elapsed shown) corresponds to role
  literally holding the string 'human'... not to role being null or absent, so detecting it is a value
  comparison against that string, not a presence check."
- **Artifact ID:** wireframes/wireframe-hub.html
- **Section:** `#active-log`
- **Excerpt:** `<div class="field"><span class="k">STEP</span><span class="v">write-code</span></div>` /
  `ROLE` / `ELAPSED` field rows, grid `10ch 1fr`. `#needs-attention-human` shows only the STEP field
  (`code-await-merge`), no ROLE/ELAPSED rows at all - confirming AC-4 means the fields are absent, not
  blank.

### Dependencies

- WI-026 (hub must exist to add header fields to), WI-004 (role on the read path), WI-005 (elapsed-time
  computation).

### Constraints

- **AC-4 detection is a value comparison against the literal string `"human"`, not a presence/null
  check** - matching how `lane_for`/`node_queue.py` already treat `role == "human"` as first-class.
- Elapsed value/format reused from WI-005/WI-012 - not recomputed independently.

### Verification

- Pilot test: an active worker-performed step shows STEP, ROLE, and ELAPSED.
- Pilot test: a human step (`role == "human"`) shows STEP only, no ROLE or ELAPSED field rendered at all
  (not blank values).
- Regression: elapsed-time value matches the same figure WI-012 would show for the same item on the
  priority list.

### Deliverable

The hub header correctly shows STEP/ROLE/ELAPSED for a worker-performed step and STEP-only for a human
step.
