## WI-018: See which project an item belongs to

**Brief:** Add a project column to every priority list row (needs-attention, active, queued alike),
resolved via the same `project_of()` artifact-based derivation the Backlog already uses - not the node's
own `project` field, which is populated independently and can disagree.

### Acceptance Criteria

Copied verbatim from the source story:

- Given an item appears in the priority list - needs-attention, active, or queued, when it renders, then
  its owning project is shown alongside it, so it's attributable at a glance without opening it.
- Given an item has no registered project, when it renders, then the project field is blank, same
  convention as the Backlog.

### Dependencies

- WI-010.

### Constraints

- **Must call `project_of()` (the artifact-based derivation confirmed live at
  `application/work/project_of.py`), not read `Node.project` directly** - using the wrong field would
  silently disagree with the Backlog's own project column for any item where the two diverge.
- Blank rendering for unregistered items, matching the Backlog's existing convention exactly (no
  placeholder text).

### Verification

- Pilot test: a fixture item with a "repo" artifact renders the correct project label via `project_of()`.
- Pilot test: a fixture item with no "repo" artifact renders a blank project field, not a placeholder.
- Regression: confirm the priority list's project value matches what the Backlog would show for the same
  item (same derivation, not two independently-computed values).

### Open Questions

- `[builder]` Whether project-label resolution (identity → display name, and the `project_of()` artifact
  lookup itself) is implemented once in a shared location all three call sites draw from (this item, plus
  WI-026's hub header and WI-050's Backlog) or resolved independently per screen - the API Contracts
  artifact explicitly leaves this open, same shape of question as WI-005's elapsed-time computation.
  Whichever this item picks, WI-026 and WI-050 should reuse it rather than re-deciding independently.

### Deliverable

Every priority list row shows its owning project via the same derivation the Backlog uses, blank when
unregistered.
