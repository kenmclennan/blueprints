## WI-045: Live log tail as written + auto-scroll + return without losing position

**Brief:** The Log tab tails its worker's log file by byte offset (independent of the 10-second poll
loop), appending new lines and auto-scrolling to keep them visible. Detects the moment the step completes
in order to stop tailing (the finished-indicator UI itself is WI-048's own scope, not this item's).
Closing returns to wherever the log was opened from, at its prior position.

### Acceptance Criteria

Copied verbatim from "See the live log tail as it's written":

- Given the current step is being performed by a worker, when I open its live log, then new lines appear
  as they're written, without manual refresh.
- Given the live log is open and following the tail, when a new line arrives, then the view auto-scrolls
  to keep it visible.

Copied verbatim from "Return to the node without losing position" (log variant):

- Given I opened the live log from a node's hub view, when I close it with Esc or ←, then the hub view
  reappears as it was.

### Dependencies

- WI-028 (contextual tab landing, which is how an active node reaches the Log tab in the first place).

### Constraints

- **This item detects step completion only to stop its own tail** - rendering the "step finished"
  indicator and retaining the accumulated log is WI-048's explicit scope, not duplicated here.
- File tailing is independent of the 10-second poll loop - a separate mechanism, established here for
  WI-047/048/049 to build on.
- Esc/← exits the node back to wherever it was opened from (priority list, hierarchy, backlog) at that
  screen's prior position - not a step back to a previously-active tab within the hub.

### Verification

- Pilot test: simulating new lines written to a fixture log file shows them appearing live, with
  auto-scroll keeping the newest line visible.
- Pilot test: closing the log (opened from the priority list) returns to the priority list at its prior
  position; closing the log (opened from the hierarchy) returns to the hierarchy at its prior position.

### Deliverable

Live log tailing works correctly with auto-scroll, and closing correctly returns to whichever screen the
node was opened from.
