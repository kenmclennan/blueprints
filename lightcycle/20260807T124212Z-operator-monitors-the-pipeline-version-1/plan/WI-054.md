## WI-054: Quiet message when the backlog is empty (overall vs. filtered)

**Brief:** When the current filter's result set is empty, distinguish "the backlog is genuinely empty
everywhere" from "empty only under this project filter" - the message must make clear which is true, so
filtering never reads as "no backlog work exists at all." Requires knowing both the filtered count and
whether the backlog has anything at all, not just re-reading the current filter's own empty result.

### Acceptance Criteria

Copied verbatim from the source story:

- Given no todo items exist under the current filter, when the backlog renders, then a calm message is
  shown in place of the list, not a blank area.
- Given the message is shown because a project filter is active, not because the backlog is empty
  overall, when I read the message, then it makes clear the filter is what's empty, so I know to check
  'All' rather than assume there's no backlog work at all.
- Given an item later becomes available under the current filter, when that happens, then the message is
  replaced by the list showing that item.

### Dependencies

- WI-050, WI-008 (the all-at-once counts this item uses to distinguish overall-empty from filter-empty -
  the same read path WI-053's picker depends on, reused here for a different purpose).

### Constraints

- **Both message variants and the hint text are literal strings from the wireframe** - "Nothing in the
  backlog." / "No backlog items for lightcycle." / "Press f to check All." - not paraphrasable, and the
  project name is interpolated into the filtered message.
- Footer shortcut set differs between the two empty states (per WI-024's contextual mechanism) - the
  overall-empty state drops `f` (nothing to filter into), the filter-empty state keeps it.

### Verification

- Pilot test: a fixture with zero backlog items anywhere shows "Nothing in the backlog." with the
  narrower `tab`/`q` footer.
- Pilot test: a fixture with backlog items existing overall but zero under the active project filter
  shows "No backlog items for `<project>`." plus the hint, with `f` still present in the footer.
- Pilot test: an item later appearing under the active filter (simulated poll) replaces the message with
  the list.

### Deliverable

The backlog correctly distinguishes and renders both empty-state messages, with matching contextual
footers.
