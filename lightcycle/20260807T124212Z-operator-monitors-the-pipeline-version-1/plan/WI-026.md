## WI-026: Open the item detail view + return to the list without losing position

**Brief:** Selecting a priority-list row and confirming opens the item's detail view (the hub),
replacing the list full-screen (Single View, No Split Panes). Closing it returns to the priority list at
the same row and scroll position. Bundled as one work item - a drill-down with no way back is not
releasable (One Navigation Contract).

### Acceptance Criteria

Copied verbatim from "Open the item detail view":

- Given the priority list is showing, when I select a row and press Enter or →, then the item's detail
  view opens, replacing the list on screen.
- Given the detail view has just opened, when it renders, then it shows the item's identity - id, title,
  owning project, theme (if it has one), and the workflow it's running under (if any).
- Given the item has a description, when the detail view renders, then the description is shown in the
  header, below the identity fields.
- Given the item has no description, when the detail view renders, then no description line is shown.

Copied verbatim from "Return to the list without losing position":

- Given I opened an item's detail view from a specific row, when I close it with Esc or ←, then the
  priority list reappears with that row still selected and the same scroll position.
- Given I scrolled or navigated within the detail view itself, when I return to the list, then the list's
  scroll position is unaffected by anything I did inside the detail view.

### Dependencies

- WI-014 (a navigable priority list to open a row from), WI-018 (project-label resolution - AC-2 requires
  "owning project" in the header; added during this plan's own Pass 7 adversarial review, which found this
  edge missing despite WI-018's own text already naming this item as a consumer).

### Constraints

- Reuses WI-015's identity-based selection tracking for the return trip - does not re-derive "same
  position" independently; if the list reordered while the hub was open, land on the identity-tracked
  row, not a raw saved index.
- Description line is conditionally rendered - absent, not empty, when the item has none.

### Verification

- Pilot test: selecting a row and pressing Enter opens the hub with correct identity fields.
- Pilot test: an item with no description renders no description line; one with a description renders it
  below the identity fields.
- Pilot test: opening then closing (Esc) returns to the list with the same row selected and scroll
  position preserved.
- Pilot test: scrolling within the hub before closing does not affect the list's restored scroll position.

### Deliverable

Any item opens into its tabbed hub with correct header fields; closing returns to the list exactly where
it was.
