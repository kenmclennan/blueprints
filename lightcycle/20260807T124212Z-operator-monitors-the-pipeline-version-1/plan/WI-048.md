## WI-048: Step finishes while watching (finished indicator retained)

**Brief:** Detect step completion the same way the pool's own sweep does - by checking whether the
worker's recorded pid is still alive AND its recorded start time still matches the live process (guarding
against pid reuse), not from a stored status flag. Show a clear "finished" indicator when detected, and
keep the accumulated log output visible, not cleared.

### Acceptance Criteria

Copied verbatim from the source story:

- Given the live log is open and the worker completes, when that happens, then the view clearly
  indicates the step has finished, not just going silent.
- Given the step has finished, when I look at the log, then it still shows the accumulated output up to
  completion, not cleared.

### Dependencies

- WI-045.

### Constraints

- **Must use the robust liveness check** (`worker_alive`/`process_start_time` comparison - confirmed live
  at `adapters/workers.py`, distinct from the bare `pid_alive` check `.lc-run.pid` uses for WI-002), since
  a bare pid-liveness check is vulnerable to pid reuse falsely reporting "still running."
- Must handle both observable states named in the story's Context - "worker still listed but dead" and
  "worker gone from the registry entirely" (post-prune) - as both meaning "finished," not just the first.
- Accumulated log output is retained, never cleared, on the finished transition.

### Verification

- Pilot test: a fixture worker whose recorded pid+start-time no longer match a live process is detected
  as finished, showing the indicator with the log retained.
- Pilot test: a fixture where the worker entry has been pruned entirely from the registry (post-sweep) is
  also detected as finished, not mistaken for still-running.
- Pilot test: a pid-reuse fixture (dead worker's pid now belongs to an unrelated live process) is
  correctly detected as finished, not falsely "still running" - proves the start-time check matters, not
  just liveness.

### Deliverable

Step completion is reliably detected via the robust worker-liveness check, with a clear finished
indicator and the full log retained.
