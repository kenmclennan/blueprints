# WI-004 - Backlog screen

## What

The second top-level screen: the todo backlog, its project filter picker, and the navigation that moves between it and current work from any depth.

## Defined by

- [wireframe-backlog.html](../wireframes/wireframe-backlog.md) - the authoritative layout, including the `#picker-open` state and the empty states. Open the file.
- [Design System Tokens](../design-system/design-system-tokens.md) - this screen's own column grid, which differs from the priority list's, and the panel surface the picker is raised on.
- [Keyboard Navigation Scheme](../design-system/keyboard-navigation-scheme.md) - the filter key, how the picker is driven, and why the global jump key works from any depth rather than only between these two screens.
- [Domain Model](../domain-model/domain-model.md) - what todo maps to in the engine's own state vocabulary.
- [API Contracts](../api-contracts/api-contracts.md) - the picker's requirement for every registered project's count at once, and why calling the existing per-project path repeatedly is the workaround it exists to head off.
- [Screen Flow](../user-flows/screen-flow-current.md) - which transitions into and out of this screen are authorised.
- [One Navigation Contract](../principles/one-navigation-contract.md) - why back-navigation here behaves identically to every other screen.
- The stories this item delivers:
  - [See todo items not yet activated](../user-stories/a0c35689-d78b-4ee0-9cde-bab92a9648af.md)
  - [Explore a backlog item's context in the hierarchy](../user-stories/7f92f015-2d19-449f-bb47-f389e6dc9691.md)
  - [Return to the backlog without losing position](../user-stories/572ae397-7fb6-453c-832a-80700e1bd483.md)
  - [Switch to the backlog with a tab or shortcut](../user-stories/5fa1445f-dc04-4322-b1be-e00496e8d0d9.md)
  - [Filter the backlog by project](../user-stories/b4b5ce79-8c4b-4fb4-a4c9-1a040e4c6bb7.md)
  - [See a quiet message when the backlog is empty](../user-stories/addfdbfd-a67a-43f5-a343-dd2f45af15ff.md)

## In scope

- The todo list and its rows, using this screen's grid.
- The project filter picker, its counts, and applying or cancelling a filter.
- The empty state.
- The global jump between current work and backlog, working from any depth.
- Opening a backlog item into the hub, once the hub exists.

## Out of scope

- The hub itself and what it renders - WI-005. This item opens it; it does not build it.
- Footer content - WI-001 and WI-003.
- Row-rendering machinery shared with the priority list, including the project label - WI-002 owns it; reuse it here rather than writing a second copy.

## Done when

The acceptance criteria on all six stories hold.

## Notes from the codebase

The engine reads are done and covered by non-`@wip` feature files. `BacklogUseCase` (`lightcycle/application/work/backlog.py`) returns backlog rows filtered by project, and a counts path exists alongside it returning a per-project count plus unscoped and total figures - which is exactly the shape the picker needs, so the workaround the API contract warns about is already closed off.

Rows carry the raw registry identity, so the display label WI-002 derives is reused here rather than re-derived.

Where the design and the codebase disagree, the design wins.

## Open questions

- `[designer]` The design does not state whether the picker's project list shows every registered project or only those with a non-zero count. [wireframe-backlog.html](../wireframes/wireframe-backlog.md)'s `#picker-open` state is the artifact that would settle it; the counts read supplies either.
