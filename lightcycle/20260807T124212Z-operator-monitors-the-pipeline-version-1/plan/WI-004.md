# WI-004 - Backlog screen

## What

The second top-level screen: the todo backlog, its project filter picker, and the navigation that moves between it and current work from any depth.

## Defined by

- [wireframe-backlog.html](../wireframes/wireframe-backlog.html#normal) - the authoritative layout, including the [`#picker-open` state](../wireframes/wireframe-backlog.html#picker-open) and the empty states. Open the file.
- [Design System Tokens](../design-system/design-system-tokens.md) - this screen's own column grid, which differs from the priority list's, and the panel surface the picker is raised on.
- [Keyboard Navigation Scheme](../design-system/keyboard-navigation-scheme.md) - the filter key, how the picker is driven, and why the global jump key works from any depth rather than only between these two screens.
- [Domain Model](../domain-model/domain-model.md) - what todo maps to in the engine's own state vocabulary.
- [API Contracts](../api-contracts/api-contracts.md) - the picker's requirement for every registered project's count at once, and why calling the existing per-project path repeatedly is the workaround it exists to head off.
- [Screen Flow](../user-flows/screen-flow-current.md) - which transitions into and out of this screen are authorised.
- [One Navigation Contract](../principles/one-navigation-contract.md) - why back-navigation here behaves identically to every other screen.
- The stories this item delivers:
  - [See todo items not yet activated](../user-stories/a0c35689-d78b-4ee0-9cde-bab92a9648af.md)
  - [Switch to the backlog with a tab or shortcut](../user-stories/5fa1445f-dc04-4322-b1be-e00496e8d0d9.md)
  - [Filter the backlog by project](../user-stories/b4b5ce79-8c4b-4fb4-a4c9-1a040e4c6bb7.md)
  - [See a quiet message when the backlog is empty](../user-stories/addfdbfd-a67a-43f5-a343-dd2f45af15ff.md)

## In scope

- The todo list and its rows, using this screen's grid.
- The project filter picker, its counts, and applying or cancelling a filter.
- The empty state.
- The global jump between current work and backlog, for the criteria that concern the two top-level screens. The criterion covering a jump from several screens deep is owned by the item that builds the screen jumped from - WI-005, WI-006 and WI-007 each carry it.

## Out of scope

- The hub itself, opening a backlog item into it, and returning from it - WI-005, which owns both of those stories because neither can hold until the hub exists.
- Footer content - WI-001 and WI-003.
- Row-rendering machinery shared with the priority list - WI-002 owns it; reuse it here rather than writing a second copy.

## Done when

The acceptance criteria on all four stories hold, except the depth criterion assigned above.

## Notes from the codebase

The engine reads are done and locked by feature tests. `BacklogUseCase` (`lightcycle/application/work/backlog.py`) returns backlog rows filtered by project, and a counts path exists alongside it returning a per-project count plus unscoped and total figures - which is exactly the shape the picker needs, so the workaround the API contract warns about is already closed off.

Rows already carry the short project label, from the same read the priority list uses; nothing needs deriving here. [API Contracts](../api-contracts/api-contracts.md) says this value still needs resolving to a display name - that claim has aged, and `backlog-counts.feature` pins the current behaviour.

Where the design and the codebase disagree, the design wins.

## Open questions

- `[designer]` The design does not state whether the picker's project list shows every registered project or only those with a non-zero count. [wireframe-backlog.html#picker-open](../wireframes/wireframe-backlog.html#picker-open) is the artifact that would settle it; the counts read supplies either.
