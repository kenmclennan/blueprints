## WI-004: Trace/hierarchy read path carries step role

**Brief:** `TraceNode` (what the Hierarchy tab's read path returns per node today) carries `id`, `step`,
`state`, `log` - no `role`, even though the `Node` it's built from has one. Every hierarchy/hub story that
shows a step's role (write-code, review-code, human, ...) depends on closing this gap.

### Acceptance Criteria

Restated in Given/When/Then form from the two stories that hit this same gap independently (no single
story owns it as its own scope - both name it as a dependency):

- Given a step node with `role` set (e.g. `write-code`), when the hierarchy or hub's read path resolves
  that node, then the role value is available to render, not silently dropped.
- Given a step node with `role="human"`, when the read path resolves it, then that exact sentinel value
  is available to render (existing engine code already treats `role == "human"` as a first-class value,
  not an absence - see `lane_for`/`node_queue.py`'s queue filter) - the read-model change must not lose
  or reinterpret it.
- Given the change is in place, when the existing `application/work/status.py`/`queue.py` lane
  computations run, then their behavior is unchanged - this item extends a read model, it does not alter
  lane logic.

### Dependencies

None.

### Constraints

- Confirmed against live code (2026-08-11): `TraceNode` (`application/work/trace.py`) is exactly
  `(id: str, step: Optional[str], state: str, log: Optional[str])` - no `role`. Confirmed this is real,
  unbuilt work.
- Must not change `lane_for(state, role)` (`domain/work/state.py`) or any existing lane computation -
  this is a read-model extension only, consumed by the hierarchy/hub, not the pool.

### Verification

- Unit test: a step node's role survives through the extended read path unchanged, for a worker role and
  for `role="human"`.
- Regression: existing `TraceUseCase` unit tests still pass unmodified (aside from the new field being
  present).

### Open Questions

- `[builder]` Whether to extend `TraceNode` with a `role` field, switch the step read to return `Node`
  objects directly, or another shape - explicitly left open by the API Contracts artifact as a
  build-time choice.

### Deliverable

The hierarchy/hub's step read path exposes each step's `role` value (including the `"human"` sentinel)
without altering existing lane or state logic, unit-tested.
