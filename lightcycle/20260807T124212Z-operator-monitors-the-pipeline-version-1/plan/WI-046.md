## WI-046: No live log message (human step / not started)

**Brief:** When the current step has no worker (a human step, or a queued step that hasn't started),
show a clear message in the Log tab rather than a blank or broken pane.

### Acceptance Criteria

Copied verbatim from the source story:

- Given the current step is a human step (no worker), when I try to open its live log, then I see a
  message saying there's nothing live to stream, not a blank or broken pane.
- Given the current step hasn't started yet (queued), when I try to open its live log, then the same
  message applies.

### Source References

- **Artifact ID:** wireframes/wireframe-hub.html
- **Artifact Name:** Wireframe - Item / Node Hub
- **Section:** Log tab (no dedicated no-log wireframe state is included among the labelled states in this
  design's wireframe file - the Log tab's populated (`#active-log`) and finished (`#log-finished`) states
  are shown, but a no-log state is not separately mocked)

### Dependencies

- WI-045.

### Constraints

- Detection uses the same `role == "human"` value comparison already established in WI-027/031 (not a
  presence/null check), and "hasn't started" means the step's state has never reached `in_progress`
  (queued/backlogged), not merely "no current log lines yet."

### Verification

- Pilot test: opening the Log tab for a human-step node shows the message, not a blank pane.
- Pilot test: opening the Log tab for a queued (not-yet-started) node shows the same message.

### Open Questions

- `[builder]` Exact message copy - no wireframe state in this design mocks this condition, so the wording
  is a build-time choice.

### Deliverable

The Log tab shows a clear message for both no-worker cases, never a blank or broken pane.
