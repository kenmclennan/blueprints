## WI-022: Footer: upgrade available indicator

**Brief:** Call the engine's existing `upgrade()` in `check_only=True` mode to show an upgrade-available
indicator when a newer version exists, omitting the indicator entirely (never erroring) if the check
can't complete.

### Acceptance Criteria

Copied verbatim from the source story:

- Given a newer version exists upstream, when the dashboard checks, then the footer shows an 'upgrade
  available' indicator with the newer version number.
- Given the installed version is current, when the dashboard checks, then no upgrade indicator is shown.
- Given the upgrade check can't complete (e.g. no network), when that happens, then the footer just omits
  the indicator rather than erroring or blocking anything else.

### Dependencies

- WI-010.

### Constraints

- **Must call `upgrade(check_only=True)` exactly** - never the install branch. Confirmed live: when
  `check_only=True`, `holders()` (venv-busy guard) is never called and `install()` never runs, so this is
  safe to call from a read-only TUI poll.
- This is the one network reach in the whole design (per "Terminal-Native, No Server" and Quality
  Attributes' Security section) - carries no credentials, must degrade to silence on any failure, never
  block the rest of the footer or list rendering.
- 10-second timeout is already built into `fetch_remote_version()` - this item does not need its own
  timeout handling, only to not block the UI thread/render loop while waiting.

### Verification

- Pilot test: mocked `check_only=True` response with a newer version shows the indicator with the correct
  version number.
- Pilot test: mocked response with the current version shows no indicator.
- Pilot test: mocked network failure shows no indicator and does not raise/block rendering.
- Confirm via code review that only `check_only=True` is ever passed - no path can trigger an install.

### Open Questions

- `[builder]` Poll cadence for the upgrade check specifically - whether it rides the same 10-second loop
  as everything else or a longer interval (an upgrade check every 10 seconds is more network traffic than
  this quiet, low-frequency fact needs) - not specified by the design.

### Deliverable

The footer's upgrade indicator is correct when a check succeeds and silently absent when it fails,
calling only `check_only=True`.
