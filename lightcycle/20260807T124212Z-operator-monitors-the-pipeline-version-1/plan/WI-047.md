## WI-047: Scroll back through the live buffer without stopping the tail

**Brief:** Scrolling up in an open live log shows earlier buffered lines without interrupting the
underlying tail; a new line arriving while scrolled up is appended to the buffer but does not jerk the
view back to the bottom. Ctrl-U/Ctrl-D page a full screen at a time.

### Acceptance Criteria

Copied verbatim from the source story:

- Given the live log is open, when I scroll up, then I see earlier lines from the current buffer without
  stopping the live tail.
- Given I've scrolled up, when a new line arrives, then it's added to the buffer but doesn't yank my
  scroll position back to the bottom.
- Given the buffer is longer than one screen, when I press Ctrl+U or Ctrl+D, then I move through it a
  full screen at a time instead of one line at a time.

### Dependencies

- WI-045 (the live tail this item scrolls back through).

### Constraints

- The tail must continue running in the background while scrolled up - this is not a pause-on-scroll
  mechanism.
- Reuses the global Ctrl-U/Ctrl-D convention (WI-014) even though the specific wireframe footer state
  doesn't render it - the keyboard scheme document is the authoritative source, not any one wireframe's
  footer snapshot.

### Verification

- Pilot test: scrolling up in a fixture live log shows earlier lines while the tail continues.
- Pilot test: a new line arriving while scrolled up is appended without moving the visible scroll
  position.
- Pilot test: Ctrl-U/Ctrl-D page a full screen at a time through a buffer longer than one screen.

### Deliverable

Scrolling back through the live buffer works correctly without interrupting or being interrupted by the
ongoing tail.
