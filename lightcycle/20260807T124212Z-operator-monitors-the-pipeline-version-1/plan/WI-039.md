## WI-039: Artifacts tab: list attached artifacts, always-present, empty state

**Brief:** Render the current node's artifacts, filtered to non-internal only, each labeled by type. The
Artifacts tab is always present in the `[`/`]` cycle - even on a node with nothing viewable - showing a
calm empty state rather than being conditionally withheld.

### Acceptance Criteria

Copied verbatim from the source story:

- Given a node has one or more non-internal artifacts, when I open its artifact list, then each is shown
  labeled by its type (e.g. spec, branch, pr, brief).
- Given the artifact list is open, when I look at it, then only non-internal artifacts appear - internal
  bookkeeping types are never shown, consistent with the tree's content indicator.
- Given a node has no viewable artifacts, when I open its Artifacts tab, then a calm message is shown in
  place of the list, not a blank area.
- Given any node, whether or not it has viewable artifacts, when its hub is open, then the Artifacts tab
  is always present, so the Hierarchy/Log/Artifacts cycle is the same three tabs on every node.

### Constraints

- Filters on the exact same `internal` field WI-032's hierarchy content indicator already filters on -
  the two must never disagree for the same node (see WI-032's own cross-check verification).
- Always present regardless of content - this was an explicit design correction (see Context above), not
  a discretionary choice.

### Verification

- Pilot test: a node with a mix of internal/non-internal artifacts shows only the non-internal ones,
  labeled by type.
- Pilot test: a node with only internal artifacts (or none) shows the empty state, not a blank pane, and
  the Artifacts tab is still selectable/present in the `[`/`]` cycle.
- Cross-check: for the same fixture, WI-032's hierarchy content indicator and this tab's presence/
  emptiness agree.
