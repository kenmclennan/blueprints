## WI-025: Quit the dashboard

**Brief:** Bind `q` and `Ctrl+C` to a clean app exit that resolves from anywhere, regardless of which
widget currently has focus. Textual's own defaults do NOT give this for free - `q` isn't bound to quit
out of the box, and Ctrl+C is deliberately rebound by the framework to a notification rather than an
exit.

### Acceptance Criteria

Copied verbatim from the source story:

- Given the dashboard is open, at any screen, when I press q or Ctrl+C, then the TUI exits cleanly,
  returning me to the shell.

### Source References

- **Artifact ID:** user-stories/204b730c-94db-43f2-b0e0-4c685e37a038.md
- **Section:** Context
- **Excerpt:** "Textual doesn't give this behaviour for free. Out of the box, 'q' isn't bound to quit at
  all, and Ctrl+C is deliberately rebound to an action that only pops a notification naming the real quit
  key rather than exiting - both keys need an explicit binding as part of building this story, not just
  relying on framework defaults. Textual resolves an ordinary binding by walking up from whatever widget
  currently has focus, so on screens with a focusable widget in the chain... a plain App-level binding can
  be shadowed by whatever's focused at the time. Matching Textual's own default quit binding, which is
  marked priority so it resolves from the app down instead, is what makes quitting work 'at any screen'
  the way the acceptance criteria requires."

### Dependencies

- WI-010.

### Constraints

- **Must use a priority-level binding** (matching Textual's own default quit-binding mechanism), not a
  plain App-level binding - a plain binding is shadowed by whatever widget has focus (the Hierarchy tree,
  the live log view, any list widget), which would break the "at any screen" requirement on exactly the
  screens built in later milestones.
- Explicitly overrides Textual's default Ctrl+C behavior (a notification), not just adds a new binding
  alongside it.

### Verification

- Pilot test: pressing `q` from the Priority List (no widget focus) exits cleanly.
- Pilot test: pressing `q` from a screen with a focused focusable widget (test against a stub widget if
  Milestone 2+ screens don't exist yet) still exits cleanly - confirms the priority-binding requirement,
  not just the trivial no-focus case.
- Pilot test: pressing `Ctrl+C` exits cleanly rather than showing Textual's default notification.

### Deliverable

`q` and `Ctrl+C` both exit the dashboard cleanly from any screen and any focus state.
