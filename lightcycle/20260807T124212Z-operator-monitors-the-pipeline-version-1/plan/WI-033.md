## WI-033: Hierarchy: scroll with the keyboard

**Brief:** The same up/down + Ctrl-U/Ctrl-D scroll contract WI-014 already established for the priority
list, applied to the hierarchy's fully-expanded tree - nothing collapses, since everything is already
shown.

### Acceptance Criteria

Copied verbatim from the source story:

- Given the hierarchy has more rows than fit on screen, when I press up/down, then the selection moves to
  the previous/next node, scrolling as needed.
- Given the selection is at the first or last node, when I press past the end, then it stays put rather
  than wrapping.
- Given the hierarchy is longer than one screen, when I press Ctrl+U or Ctrl+D, then the view jumps by
  roughly a full screen at a time.

### Constraints

- Reuses the exact scroll mechanism WI-014 established for the priority list (see WI-014's own
  Constraints, which names this as one of the reuse sites) - do not build a second scroll implementation.
- Must not preclude WI-034's pinned-ancestor overlay row, which layers on top of this item's scrolling row
  set rather than being part of it.

### Verification

- Pilot test: arrow-key and Ctrl-U/Ctrl-D navigation through a hierarchy fixture longer than one screen,
  clamped at both ends - same test shape as WI-014's.

### Deliverable

The hierarchy scrolls via the same keyboard contract as the priority list, with no wrap-around.
