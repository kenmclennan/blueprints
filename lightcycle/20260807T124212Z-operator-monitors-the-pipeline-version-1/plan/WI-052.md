## WI-052: Explore a backlog item's context in the hierarchy + return without losing position

**Brief:** Opening a backlog entry lands on the Hierarchy tab, consistent with how any node is explored -
but a backlogged item has no step children by construction (steps are only filed at activation), so this
renders the item alone, with a theme ancestor above it only if one was already assigned pre-activation.
Closing returns to the backlog using the same identity-based re-association WI-015 established, since the
backlog is itself a live, polled screen whose contents can shift while the item's hub is open (most
directly: the very item just opened could get activated and drop out of the backlog before Esc/←
returns).

### Acceptance Criteria

Copied verbatim from "Explore a backlog item's context in the hierarchy":

- Given a backlog item is selected, when I open it with Enter or →, then its hub opens, landing on the
  Hierarchy tab, showing its place in the tree.

Copied verbatim from "Return to the backlog without losing position":

- Given I opened a backlog item's hub, when I close it with Esc or ←, then the backlog reappears at the
  same scroll/selection position.

### Dependencies

- WI-050, WI-030 (Hierarchy tab, rendering the item-alone / theme-plus-item case as a real but sparse
  instance of the general hierarchy).

### Constraints

- **Reuses WI-030's Hierarchy tab rendering, not a special-cased "backlog hierarchy" view** - this is the
  general Hierarchy tab correctly rendering a real (if minimal) tree: item alone, or theme+item if a
  theme was pre-assigned.
- **Return-to-backlog reuses WI-015's identity-based selection tracking** - not a raw saved row index,
  since the opened item itself may be activated (and vanish from the backlog) while its hub is open.

### Verification

- Pilot test: opening a themeless backlog item shows it alone in the Hierarchy tab, no step rows.
- Pilot test: opening a backlog item with a pre-assigned theme shows the theme above it, still no step
  rows beneath the item.
- Pilot test: opening a backlog item, then simulating its activation while the hub is open, then closing
  with Esc/← lands correctly on the backlog's remaining nearest item (not a stale/now-invalid row index).

### Deliverable

Backlog items open correctly into the general Hierarchy tab (rendering their real, minimal tree), and
closing returns reliably even if the backlog's contents shifted while open.
