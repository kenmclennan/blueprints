# WI-012 - Project-filter picker's item counts never render

## What

Filed by `audit-design`, not by a story. The backlog's project-filter picker is supposed to show "All" plus every registered project, each with its own item count - the count is computed correctly and passed to the widget, but never actually paints, on any terminal width, regardless of how many projects are registered.

## Reproduced

Verified against `origin/main` at `6cee3b9`. [wireframe-backlog.html#picker-open](../wireframes/wireframe-backlog.html) shows `All 13`, `lightcycle 1`, each row's count right-aligned. [`Filter the backlog by project`](../user-stories/b4b5ce79-8c4b-4fb4-a4c9-1a040e4c6bb7.md) AC-1 states the picker "shows 'All' plus every registered project, each with its own item count."

Built a store with a registered project and real backlog items, opened the picker, and read the composited frame - every row shows only the label, no number at all, at both 100×30 and 120×30, regardless of how many projects are registered:
```
│ Filter by project                    │
│──────────────────────────────────────│
│ ❯ All                                │
│   bar                                │
│   empty-proj                         │
│   foo                                │
```
Inspecting the live widgets directly confirms the data is present but the count widget has essentially no room to draw in: `PickerOption`'s label `Static` (`app.py:297`) has no explicit `width` in `ProjectFilterPicker`'s CSS, so it expands to fill nearly the whole 40-cell picker box (`Size(width=36, height=1)`), leaving the `.picker-option-count { width: 1fr; ... }` `Static` a `Size(width=1, height=1)` sliver its digits don't fit in. This is not a missing-data problem - `BacklogUseCase.counts()` and `LightcycleApp.action_open_picker` compute and pass the real counts correctly (`backlog-counts.feature`, 9/9 passing) - it's a pure layout bug in the picker's own CSS that silently drops the count text before it reaches the screen.

## Defined by

- [wireframe-backlog.html](../wireframes/wireframe-backlog.html) - `#picker-open`, every row's right-aligned count.
- [Filter the backlog by project](../user-stories/b4b5ce79-8c4b-4fb4-a4c9-1a040e4c6bb7.md) - AC-1.

## In scope

- Constraining the picker's label `Static` to leave room for its count `Static`, so both render together on every row, matching the wireframe.

## Out of scope

- The row-grid column-overflow issues filed separately as WI-008 - this is a distinct root cause (a missing width constraint, not a column too narrow for its content).
- The picker's apply/cancel/navigation behaviour, and the filter bar's own single-filter count display - both already verified correct.

## Done when

Every row in the project-filter picker shows its item count, right-aligned, alongside its label, verified on the actual composited frame with a registered project set large enough to need the full width.
