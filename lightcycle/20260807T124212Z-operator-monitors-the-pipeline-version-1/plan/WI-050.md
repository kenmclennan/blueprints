## WI-050: Backlog screen: todo list + project column + Ctrl-U/D scroll

**Brief:** Build the interactive Backlog screen - cursor movement, Ctrl-U/Ctrl-D paging - over the
already-correct `BacklogUseCase` data path, which already selects `BACKLOGGED` items, already supports a
project filter, and already returns each row's project via `HumanNodeRow.project`. The existing
`lc backlog` CLI output is a static one-shot print with no cursor/selection/paging - this item's real
scope is the interactive TUI layer, not the query logic underneath it.

### Acceptance Criteria

Copied verbatim from the source story:

- Given items exist in todo state, when I switch to the backlog, then they're listed.
- Given a todo item is later activated, when that happens, then it no longer appears in the backlog.
- Given the backlog is longer than one screen, when I press Ctrl+U or Ctrl+D, then the view jumps by
  roughly a full screen at a time.
- Given an item appears in the backlog, when it renders, then its owning project is shown alongside it,
  so it's attributable at a glance without opening it.

### Constraints

- **Correction found during this plan's own Pass 7 adversarial review**: the source story's own Context
  (quoted above) is correct that `BacklogUseCase`'s selection, filtering, and blank-when-unregistered
  behavior are already correct and need no new work - but `HumanNodeRow.project` (via `project_of()`) is
  the raw registry identity (`owner/name`), not the short display label the wireframe shows
  (`"lightcycle"`, not `"kenmclennan/lightcycle"`). Reusing the query path is correct; reusing its raw
  `project` value as the display string directly is not. **This item must apply WI-018's identity-to-
  display-label resolution to the value `BacklogUseCase` returns**, not render it verbatim - otherwise the
  Backlog and the Priority List (WI-018) would visibly disagree on the same project's label, which is
  exactly the fidelity failure a shared resolution mechanism (WI-018's own Open Questions) exists to
  prevent.
- Row grid is `2ch 9ch 10ch 1fr` (cursor, id, project, title) - no step or elapsed-time columns, since
  backlog items haven't started.
- Reuses the global Ctrl-U/Ctrl-D scroll convention.

### Verification

- Pilot test: a fixture with backlogged items renders them all, each with correct project attribution
  (blank when unregistered, per the same convention as the Priority List's WI-018).
- Pilot test: an item transitioning from `BACKLOGGED` to activated (across a simulated poll) disappears
  from the backlog list.
- Pilot test: Ctrl-U/Ctrl-D pages a backlog longer than one screen.

### Deliverable

The Backlog screen lists todo items with project attribution, live-updating and pageable, over the
existing correct query path.
