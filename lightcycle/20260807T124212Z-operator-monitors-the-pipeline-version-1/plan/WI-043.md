## WI-043: Open a file-path artifact in its application

**Brief:** Open a `filepath`-kind artifact via a small cross-platform subprocess launcher (`open` on
macOS, `xdg-open` on Linux - a resolved architectural decision). Toast-and-return, same pattern as
WI-042's URL handling. A clear message if the file no longer exists at that path.

### Acceptance Criteria

Copied verbatim from the source story:

- Given an artifact declares kind `filepath`, when I select it with Enter or →, then it opens via the
  OS's default handler for that file type.
- Given the file no longer exists at that path, when I select it, then I see a clear message rather than
  a silent failure or crash.
- Given the file opens successfully, when that happens, then the TUI shows a brief confirmation toast and
  returns to the artifact list - there's no separate viewer screen to sit in, since the external
  application has taken over.

- WI-040, WI-001.

### Constraints

- Platform scope is macOS/Linux only, per the architecture doc's own resolved decision - no Windows
  handling required.
- No separate viewer screen for this kind - toast-and-return is the entire surface.
- The architecture doc calls this launcher "a contained adapter" explicitly - implement it as a small
  driven adapter behind a port (the same pattern `SqliteStore`/git already follow), called by the TUI's
  driving-adapter code, not as an inline `subprocess` call in screen widget code. Same boundary reasoning
  as WI-042's `webbrowser.open()` call - the two share this constraint, not two independent decisions.

### Verification

- Pilot test: a `filepath`-kind artifact pointing at a real file triggers the subprocess launcher and
  shows the confirmation toast, returning to the artifact list.
- Pilot test: a `filepath`-kind artifact pointing at a non-existent path shows a clear failure message,
  not a crash or silent no-op.

### Deliverable

File-path artifacts open correctly via the OS default handler with a working toast-and-return flow and a
clear message for a missing file.
