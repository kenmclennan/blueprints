## WI-023: Footer: claude availability indicator + reclaim display

**Brief:** Wire the footer's claude-availability segment to WI-003's breaker-state use case, next to the
pool status. When the breaker is open, show the recovery time. This story also asserts (without
introducing new behavior) that any worker killed by a breaker trip already reverts to `ready`/queued via
the engine's existing reclaim mechanism - the TUI just has to render that real state accurately.

### Acceptance Criteria

Copied verbatim from the source story:

- Given the circuit breaker is closed, when I view any screen, then the footer's status line shows
  "claude available" in its default styling, next to the pool status.
- Given the circuit breaker is open, when I view any screen, then the footer's status line shows "claude
  unavailable" plus the time it will next probe for recovery (e.g. "resumes 14:32:00"), styled as an
  alert.
- Given the breaker opened while a step's worker was running and that worker was killed and reclaimed
  back to ready, when I open that node, then the hub shows its real current state (queued, not active) -
  the same reclaim behavior the engine already applies to any lost worker, not new behavior this
  indicator introduces.
- Given the breaker closes again, when the next poll runs, then the footer returns to "claude available"
  without requiring a restart.

### Dependencies

- WI-010, WI-003 (read-only breaker-state use case).

### Constraints

- **This item introduces no new reclaim logic** - the `in_progress → ready` transition on a lost worker
  already exists in the engine (confirmed: `claim_ready`/reclaim path is standing behavior). This item's
  scope is strictly the footer indicator plus confirming existing screens (priority list rows, hub state)
  already render the post-reclaim state correctly with no breaker-specific special-casing.
- "Available" styling uses `--cyan` (matches `pool running`); "unavailable" uses `--red` and is
  explicitly called an "alert" styling.

### Verification

- Pilot test: mocked breaker `{is_open: false}` shows "claude available" in default styling.
- Pilot test: mocked breaker `{is_open: true, reset_at: <time>}` shows "claude unavailable · resumes
  <time>" in alert styling.
- Pilot test: a fixture item that was active, then reclaimed to `ready` (simulating a breaker-killed
  worker), renders as queued when opened - confirming no special-case logic was needed, only that WI-013
  (queued group) and Milestone 2's hub already read live state correctly.
- Pilot test: breaker transitioning open→closed across two poll ticks updates the footer without restart.

### Deliverable

The footer's claude-availability indicator is correct in both states with recovery time when open, and a
reclaimed node renders its true (queued) state with no special-case code required.
