# WI-002 - Priority list renders current work

## What

The landing screen becomes the priority list the design specifies: needs-attention, active and queued as three fixed-order groups, each row carrying the fields the grid defines, with the bell ringing on entry to needs-attention.

## Notes from the codebase

At `b2aa7b6` the landing screen renders a `DataTable` fed by `QueueUseCase`, with column headers and the columns in engine order. Both the widget choice and the data source are wrong against this design: the queue lane is one of the three groups, not the whole list, and the design's grid has neither headers nor that column order. Treat the existing table as scaffolding to replace, not a starting shape to extend.

The engine reads this item needs all exist and are covered by non-`@wip` feature files:

- Lanes come from `StatusUseCase` (`lightcycle/application/work/status.py`), which returns all four raw lanes; the merge into needs-attention has no engine equivalent and happens here.
- `Node.blocked_by` carries the blocking ids the dependency indicator needs.
- `Duration.elapsed_since_claim(now)` (`lightcycle/domain/feedback/duration.py`) returns a `timedelta` from a step's first `IN_PROGRESS` transition. **There is no formatter anywhere in the codebase** - turning that into the display ladder the wireframe shows is part of this item, and it is the piece the hub's header will reuse.
- `project_of(store, item)` (`lightcycle/application/work/project_of.py`) returns the raw registry identity, not the short display label the wireframe rows show. Deriving the label is part of this item; it is consumed again by WI-004 and WI-005.
- `PlannedStepsUseCase` supplies a queued step's next step name.

Where the design and the codebase disagree, the design wins.

## Open questions

- `[builder]` Whether `DataTable`, a custom `ListView`, or hand-rendered rows can honour the column grid exactly. The grid is not negotiable; the widget is. A widget whose native rendering fights the grid is the wrong widget, not a reason to move the grid.
- `[builder]` Whether elapsed formatting and the project label live in the use-case layer or the adapter. [API Contracts](../api-contracts/api-contracts.md) states the trade-off and asks for it to be decided deliberately; either answer is acceptable, but both must land in one place that WI-004 and WI-005 can reuse.
