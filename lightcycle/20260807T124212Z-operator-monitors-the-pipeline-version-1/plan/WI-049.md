## WI-049: Done step's historical log

**Brief:** For a step that's already `done`, show its complete log output as a static, scrollable read -
no live indicator, no auto-scroll, since nothing new will arrive. Resolution uses WI-007's durable
log-path resolution so this works even when the step's worker registry entry has been pruned.

### Acceptance Criteria

Copied verbatim from the source story:

- Given the current step is done, when I open its Log tab, then it shows the complete log output captured
  from that step's run.
- Given a done step's log is open, when I view it, then no live-tail behaviour is shown - no 'live'
  indicator, no auto-scroll - since nothing new will arrive.
- Given the done step's log is longer than one screen, when I press Ctrl+U or Ctrl+D, then I move through
  it a full screen at a time, same as the live log.

### Dependencies

- WI-045 (Log tab base), WI-007 (durable done-step log resolution, so this works regardless of worker
  registry pruning state).

### Constraints

- **Must use WI-007's resolution path**, not the raw registry scan WI-045's live-tail path may use for an
  active step - a done step's registry entry is not guaranteed to still exist.
- No live-tail UI chrome (no "live" indicator, no auto-scroll) - this is a deliberately different render
  mode from WI-045/047/048, not the live viewer with tailing simply turned off.
- Reuses the global Ctrl-U/Ctrl-D convention for paging.

### Verification

- Pilot test: opening the Log tab for a done step (registry entry still present) shows the full static
  log, no live chrome.
- Pilot test: opening the Log tab for a done step whose registry entry has been pruned still resolves and
  shows the full log (proves reliance on WI-007, not a lucky registry hit).
- Pilot test: Ctrl-U/Ctrl-D pages a long done-step log a full screen at a time.

### Deliverable

Done steps show their complete historical log as a static, paged, non-live read, reliably regardless of
worker registry pruning.
