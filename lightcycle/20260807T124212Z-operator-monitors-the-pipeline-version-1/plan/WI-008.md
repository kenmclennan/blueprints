# WI-008 - Row-grid columns hold under realistic id and role lengths

## What

Filed by `audit-design`, not by a story - this is a fidelity gap the design's own row grids create against realistic data, found by running the built screens rather than reading their code. Every fixed-width `id` column in the row grids (Priority List, Backlog, Hierarchy), and the Hierarchy tab's `role` column, silently breaks once real content exceeds the token width: the Priority List wraps the id onto a second line, corrupting the one-row-per-item grid every other story assumes; the Backlog and Hierarchy tabs instead hard-truncate the id or role with no ellipsis, silently dropping characters so two different nodes can render an identical, ambiguous label. None of this is theoretical - it reproduces with realistic ids and role names, not contrived extremes.

## Why this is a design gap, not just a build defect

[Ontology](../glossary/ontology.md)'s own "Identity" section states a project's shortcode is "Explicit at registration (`--shortcode`) or defaulted from identity's name segment, uppercased" - and the engine's default (`identity.split("/")[-1].upper()`, `lightcycle/application/setup/project_scan.py`) is genuinely unbounded: a project registered without an explicit short code gets its whole repo name as its shortcode (e.g. `LIGHTCYCLE`, ten characters, not the two-character `LC` every wireframe and demo fixture happens to use). Every id in that project then nests off an already-long root (`LIGHTCYCLE-3.1.1` is sixteen characters), and [Design System Tokens](../design-system/design-system-tokens.md)' "Row grid conventions" table fixes the `id` column at `9ch` (Priority List, Backlog) or `13ch` (Hierarchy) with no stated overflow behaviour. The wireframes never render an id anywhere near these widths, so the gap was never visible in the design itself - only in the running app, against ids the design's own domain model already permits.

The Hierarchy tab's `role` column (`14ch`) has the same shape of problem from a different source: real step/role names in this very Blueprint's own workflow exceed it (`implement-features` is nineteen characters, `handle-feedback` is fifteen), so the same silent hard-truncation applies there too.

## Reproduced

All three, against `origin/main` at `6cee3b9` via `tests/support/tui_harness.py` reading the actual composited frame (`session.app.screen._compositor.render_strips()`), not a widget's own report of itself:

- **Priority List wraps the id, breaking the one-line-per-row grid.** With the repo's own demo data (`tests/support/screen_render.py`'s `_populated_store`), every three-segment step id wraps:
  ```
  │ ❯   ●     LC-143.3.  lightcycle  await merge                          code-await-merge           │
  │           6                                                                                      │
  ```
  `LC-143.3.6` is ten characters against a nine-character column. Reproduced independently with a plain `FakeStore`-generated id (`fake-56f47088`) too - not specific to this project's numbering.
- **Backlog silently truncates the id, with no ellipsis - two different long ids would render identically.** A todo item with a fourteen-character id (`fake-a72427b9`) renders as:
  ```
  │ ❯   fake-a724              Some backlog item                                                     │
  ```
  the trailing `27b9` is simply gone from the frame, not indicated as cut.
- **Hierarchy tab truncates both id and role the same way.** With a project using the engine's own default (unshortened) shortcode, `LIGHTCYCLE-3.1` (an item) and `LIGHTCYCLE-3.1.1` (its step) both render as the identical `LIGHTCYCLE-3.`:
  ```
  │ ○         LIGHTCYCLE-3   Theme title                                                             │
  │ ○         LIGHTCYCLE-3.    Item title                                                            │
  │ ○         LIGHTCYCLE-3.      write the code                                       write-code     │
  ```
  and a step with `role="implement-features"` renders its role cell as `implement-feat` - hard-cut mid-word, no `…`.

## Defined by

- [Design System Tokens](../design-system/design-system-tokens.md) - "Row grid conventions", the `id`/`role` column widths this item must make safe (or the widths themselves are what this item may need to revise - see Open questions).
- [Ontology](../glossary/ontology.md) - "Identity", the shortcode rule that makes id length genuinely unbounded.
- [wireframe-priority-list.html](../wireframes/wireframe-priority-list.html), [wireframe-backlog.html](../wireframes/wireframe-backlog.html), [wireframe-hub.html](../wireframes/wireframe-hub.html) - every row in every state they show is one line; none renders an id anywhere near the token widths, which is why this gap wasn't visible in the design itself.
- WI-002, WI-004, WI-005's own "done when" clauses, each of which already states rendering must be verified on the actual frame, not a widget's self-report - the standard this item is held to is the one those items already set, applied against data those items' own fixtures didn't exercise.

## In scope

- Deciding and implementing an overflow strategy for the `id` column in the Priority List, Backlog, and Hierarchy tab, and the `role` column in the Hierarchy tab, that never silently drops characters and never wraps a row onto a second line. Truncation with a visible ellipsis, a wider column, an id-shortening convention, or something else - the requirement is that the operator can always tell the row was cut, and two distinct real ids never render identically.
- Confirming the fix holds against the engine's own default (unshortened) shortcode, not just against short ones like this project's `LC`.

## Out of scope

- Changing the shortcode-derivation rule itself (`lightcycle/application/setup/project_scan.py`) - that is engine behaviour this design observes, not something this Blueprint owns.
- Any other column in these grids (`project`, `title`, `time`, `content`) - not evidenced as broken by this pass.

## Done when

No id or role cell in the Priority List, Backlog, or Hierarchy tab ever wraps a row onto a second line or drops a character silently, verified on the actual composited frame (not a widget's own `render_line`) against both this project's short (`LC`) ids and a project using the engine's own default, unshortened shortcode.

## Open questions

- `[designer]` Whether the fix is a wider column (and if so, how wide is enough against a genuinely unbounded shortcode), a truncation-with-ellipsis convention, or an id-shortening display rule (e.g. eliding the shortcode once ancestry is already shown via indentation in the Hierarchy tab). The three affected screens may not need the same answer.
