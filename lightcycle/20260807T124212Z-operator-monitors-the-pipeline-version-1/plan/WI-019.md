## WI-019: Hear an alert when something needs me

**Brief:** Fire a terminal bell (`App.bell()`, emitting `\a`) the moment the poll-diff step detects an
item transitioning into needs-attention (inbox or blocked) - not on every poll while it stays there, not
on entry to active/queued. This hooks off the exact same diff step that already drives selection-follows
and the needs-attention grouping, not a second watcher.

### Acceptance Criteria

Copied verbatim from the source story:

- Given an item enters the inbox or blocked bucket, when that happens, then a terminal bell fires.
- Given the dashboard is running in an unfocused terminal tab or pane, when an item enters inbox or
  blocked, then the bell still fires.
- Given an item is already in the needs-attention bucket, when nothing new enters, then no bell fires
  again for that same item - only on the transition into the bucket.

### Dependencies

- WI-011 (needs-attention bucketing must exist to detect the transition into it).

### Constraints

- Must reuse the existing poll-diff step (from WI-010/WI-011), not introduce a second watcher mechanism
  that could drift out of sync with the diff-based grouping.
- The TUI does nothing focus-aware itself - "still fires when unfocused" is a property of `App.bell()`
  emitting a real BEL character, not something this item implements as focus-detection logic.

### Verification

- Pilot/unit test: simulating a poll-diff where an item transitions into needs-attention triggers exactly
  one `App.bell()` call.
- Pilot/unit test: simulating consecutive polls where the item stays in needs-attention triggers no
  further bell calls.
- Pilot/unit test: an item entering active or queued (not needs-attention) triggers no bell.

### Deliverable

The bell fires exactly once per needs-attention transition, sourced from the existing poll-diff, with no
duplicate watcher.
