## WI-003: Read-only breaker-state use case

**Brief:** Add a read-only use case returning `{is_open, reset_at}` for the pool's circuit breaker.
`is_open`/`reset_at` are real and persisted (`logs/breaker.json`) but today only readable via transient
`lc start` log lines ("breaker opened until HH:MM:SS" / "breaker closed") - not a queryable current
state. The footer's claude-availability indicator (WI-023) needs this on demand, every poll.

### Acceptance Criteria

Restated in Given/When/Then form from the named API Contracts gap (no dedicated story owns this engine
gap - it's consumed by "See whether Claude is available to process work", WI-023):

- Given the breaker's persisted state has `is_open=false`, when the new use case is called, then it
  returns `is_open=false` and whatever `reset_at` value is currently persisted (irrelevant while closed).
- Given the breaker's persisted state has `is_open=true` with a `reset_at` timestamp, when the new use
  case is called, then it returns `is_open=true` and that `reset_at` value, on demand, with no dependency
  on a `lc start`/`tick` cycle having just run.
- Given the breaker transitions from open to closed (or the reverse) between two calls, when the use case
  is called again, then it reflects the new persisted state - it is not a cached snapshot from the
  first read.

### Dependencies

None.

### Constraints

- Confirmed against live code (2026-08-11): `Breaker` (`domain/pool/breaker.py`) is exactly
  `(is_open: bool = False, reset_at: Optional[float] = None)`. No read-only use case exists - the only
  surfacing today is `cli.py`'s log-line rendering inside `tick`'s pool-loop output
  (`result.breaker_opened`/`result.breaker_closed` flags), gated behind an actual `tick` call, not a
  standalone query.
- Must be read-only - do not route through `BreakerGateUseCase` (which evaluates and saves state as a
  side effect of a pool tick); read the persisted state directly.

### Verification

- Unit test: closed breaker returns `is_open=false`.
- Unit test: open breaker returns `is_open=true` plus the persisted `reset_at`.
- Unit test: two calls across a state change both reflect their own call-time state (no caching).
- Confirm the read path never calls `BreakerGateUseCase` or triggers a tick.
