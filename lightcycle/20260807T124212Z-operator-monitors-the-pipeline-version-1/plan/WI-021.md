## WI-021: Footer: engine version

**Brief:** Show `lightcycle.__version__` in the footer at all times. A static string for the life of the
process - no polling, no use case, no wiring into the 10-second refresh loop.

### Acceptance Criteria

Copied verbatim from the source story:

- Given the dashboard is open, when I look at the footer, then the installed lightcycle version is always
  shown (e.g. 'v0.42.1').
- Given lightcycle's version changes (e.g. after an upgrade and restart), when I next open the dashboard,
  then the footer reflects the new version, not a stale one.

### Source References

- **Artifact ID:** user-stories/131f76a9-7b9b-4d70-889c-5c0e9c9a0d3d.md
- **Section:** Context
- **Excerpt:** "The installed version is a static string - `lightcycle.__version__` in

  process. It has no row in store.db and needs no read-only use case or wiring into the footer's
  10-second poll loop... only a restart changes it, which is exactly what AC-2 already describes."
- **Artifact ID:** wireframes/wireframe-priority-list.html

### Dependencies

- WI-010.

### Constraints

- Read `lightcycle.__version__` directly (confirmed live at `lightcycle/__init__.py:__version__`) - no
  use case, no poll-loop wiring; AC-2's "reflects the new version on next open" is satisfied by reading
  it once at launch, since only a restart changes it.

### Verification

- Pilot test: footer displays the running process's `lightcycle.__version__` value.
- Unit test: no poll-loop call is made for this value (confirms it's read once at launch, not per-tick).

### Deliverable

The footer always shows the correct installed version, read once at launch.
