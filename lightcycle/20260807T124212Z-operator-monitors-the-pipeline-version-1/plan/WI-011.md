# WI-011 - Log tab's live "now" cue

## What

Filed by `audit-design`, not by a story. Nothing in the Log tab visually distinguishes a live, actively-tailing log from a static one while it's running - the wireframe's explicit "current line is bright, cyan blinking cursor" treatment isn't built, so a person watching the tab has no visual confirmation it's live until the moment it finishes.

## Reproduced

Verified against `origin/main` at `6cee3b9`. [wireframe-hub.html](../wireframes/wireframe-hub.html)'s CSS is explicit: `.log-line { color: var(--dim); } .log-line.now { color: var(--text); } .log-cursor { color: var(--cyan); }`, and its live-tail example's last line is `<div class="log-line now">14:03:47 running fast tier... <span class="log-cursor">▌</span></div>` - every prior line dim, the newest line bright, ending in a cyan cursor glyph.

`NodeHubScreen._apply_tail_result` (`hub.py:697-707`) instead writes every batch of tailed bytes with one uniform style: `log_pane.write(Text(result.data.decode(...), style=COLOURS["dim"]))`. There is no per-line distinction and no cursor glyph anywhere in the Log tab code. `python -m tests.support.screen_render hub#active-log --colour` confirms it: all four log lines, including the newest, render at RGB `(110,110,120)` = `--dim`; none render at `--text` `(224,224,224)`, and `▌` appears nowhere in the frame. Driving a live session directly (worker alive, actively tailing) confirms the same at runtime, not just in the fixture: the most-recently-written line is styled identically to lines written seconds earlier. The only way to tell a log is "live" today is to leave the tab open and later see the "✓ step finished" marker appear - there is no visible live indicator while it's actually live.

## Defined by

- [wireframe-hub.html](../wireframes/wireframe-hub.html) - the `.log-line.now` / `.log-cursor` treatment.
- [See the live log tail as it's written](../user-stories/28a501f3-8018-418b-b0f0-f068a928eb2c.md).

## In scope

- Styling the most-recently-written line of a live tail at `--text` rather than `--dim`, and rendering the cyan cursor glyph after it, matching the wireframe.
- Reverting a line to `--dim` once a newer line supersedes it as "now".

## Out of scope

- The historical (done-step) log rendering, which the wireframe gives no `.now`/cursor treatment to and story `3c609f13` already covers separately.
- Anything already filed as WI-006's original scope, or as LC-273/275/277/282/284/289.

## Done when

The most recently tailed line of a live log renders at `--text` with a trailing `--cyan` cursor glyph while the tail is live, verified on the actual composited frame with colour extraction, and reverts correctly as new lines arrive.
