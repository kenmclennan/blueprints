## WI-035: Hierarchy: current node highlighted at actual depth

**Brief:** Highlight whichever node the hub is currently open for, at its real position in the tree - top
row for a root theme/item, one level under a theme, or one level under a parent item for a step, since
the parent chain never goes deeper than theme > item > step.

### Acceptance Criteria

Copied verbatim from the source story:

- Given the current node is a root item or theme with no parent, when I view the Hierarchy tab, then it's
  highlighted at the top row.
- Given the current node is nested under a theme and/or a parent item, when I view the Hierarchy tab,
  then it's highlighted at its actual depth, not the top row.

### Constraints

- The tree is bounded to exactly three depths (theme, item, step) - highlighting logic does not need to
  handle arbitrary nesting.

### Verification

- Pilot test: opening a root theme/themeless item highlights the top row.
- Pilot test: opening an item under a theme highlights it at depth 1.
- Pilot test: opening a step highlights it at its correct depth under its parent item.

### Deliverable

The current node is always highlighted at its true depth in the hierarchy, for all three bounded
positions.
