## One Navigation Contract

**Category:** ux

**Outcome:** The operator never has to learn a new navigation scheme per screen; muscle memory from one view transfers to every other.

**Strategy:**
Arrow keys move the selection, enter/select opens, esc/back returns to exactly where you left off (no lost scroll or selection position). A persistent footer shows the shortcuts available in the current view.

**Rationale:**
We kept independently reinventing "return without losing position" per view (list, tree, artifact) - that's a sign it's one contract, not several. Exact keybindings and footer content are acceptance-criteria detail, not a principle-level decision.
