## Keep ancestry visible while I scroll

**Who:** Operator

**What:** As I scroll down through the hierarchy, the ancestor chain of whatever's currently in view (its theme and/or parent item) stays pinned to the top of the screen.

**Why:** So I always know which theme or item I'm under, even after scrolling deep into a long step list.

**Activity:** Inspect one item's journey - Understand a specific item end-to-end - its artifacts, child steps, and logs - to see what happened or why it's stuck.

**Step:** Explore the hierarchy

**Status:** ready

### Acceptance Criteria

- Given I scroll down past a node's parent item or theme, when they leave the visible scroll area, then their row stays pinned to the top instead of scrolling away.
- Given I scroll back up to where the ancestor's actual row is, when it comes back into normal view, then the pinned duplicate is no longer shown.

### Context

The one pinned-ancestor example in the wireframe opens an item (LC-143.3), which has exactly one ancestor - its theme - since the node model fixes the parent chain at theme > item > step (an item's parent is its theme, a step's parent is its item; id nesting mirrors this: LC-3, LC-3.1, LC-3.1.1). The hub's caption states the same tabbed view opens for a step too, and a step's ancestor chain is two deep - its item, then that item's theme. No reference shows the pinned state once both of a step's ancestors have scrolled out of view, so whether pinning stacks both rows or keeps showing only the nearer one is a real open question the current material doesn't settle.
