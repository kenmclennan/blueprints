## See a quiet message when there's no work at all

**Who:** Operator

**What:** When the list has nothing to show in any bucket, a calm message replaces it instead of a blank screen.

**Why:** So an empty pipeline reads as "nothing's happening" rather than "something's broken."

**Activity:** Get oriented on the pipeline - See the whole pipeline at a glance - what's active, blocked, waiting on me, and queued - the moment it changes, as long as the dashboard is running.

**Step:** Review current work status

**Status:** ready

### Acceptance Criteria

- Given no items exist in any bucket, when the list renders, then a calm message is shown in place of the list, not a blank area.
- Given an item later enters any bucket, when that happens, then the message is replaced by the list showing that item.

### Context

Ac-2's "list replaces the message" isn't a bespoke live-update path for this story - it rides the same 10-second poll-and-diff loop that drives every other refresh on this screen. The empty state is just what renders when a poll's diff produces zero rows across all three buckets; the next poll that turns up a row re-renders the list the same way selection-follows-item does. Nothing new needs building to detect the transition, and the worst case is one poll interval of lag between an item appearing and the message clearing.
