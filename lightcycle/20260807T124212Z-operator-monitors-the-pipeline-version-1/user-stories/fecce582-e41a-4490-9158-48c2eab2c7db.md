## See a dependency indicator on blocked items

**Who:** Operator

**What:** A needs-attention item blocked by another item's completion shows a dependency indicator, distinct from other blocked reasons (an escalated step, or a human step awaiting me).

**Why:** So I can tell at a glance this one isn't blocked on me - it's blocked on other work.

**Activity:** Get oriented on the pipeline - See the whole pipeline at a glance - what's active, blocked, waiting on me, and queued - the moment it changes, as long as the dashboard is running.

**Step:** Review current work status

**Status:** ready

### Acceptance Criteria

- Given an item is blocked specifically because it depends on another item's completion, when it appears in the priority list, then it shows a dependency icon alongside its usual needs-attention marker (not instead of it), plus the blocking item's id shown inline (e.g. 'blocked · LC-54.4').
- Given an item is blocked for a reason other than a dependency (e.g. an escalated step), when it appears in the list, then no dependency indicator is shown.

### Context

The engine's node hydration never carries a blocking item's id today, only a count. `SqliteStore._rows_to_nodes` computes `Node.deps` from `SELECT d.node_id, COUNT(*) FROM deps d JOIN nodes t ON t.id = d.blocked_by WHERE t.state != 'done' ... GROUP BY d.node_id` - and every read path that produces a `Node`, including `get_node`/`node_view` (single-item detail) and the existing `InboxUseCase`'s `HumanNodeRow`, goes through that same hydration, so none of them know which item is blocking, only how many are. The one place the engine resolves actual blocker ids is `export_rows`, a separate full-store dump that runs a per-node `SELECT blocked_by FROM deps WHERE node_id = ?` - not part of list or single-node hydration. Showing the blocking id inline (AC-1's "blocked · LC-54.4") needs that id sourced through a query that doesn't exist on this path yet. Worth noting too: a node can carry more than one unresolved dependency at once, so the wireframe's single-id format won't always have just one candidate.
