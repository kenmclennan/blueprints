## View a list artifact as a scrollable list

**Who:** Operator

**What:** An artifact declaring kind `list` displays as its own scrollable list, not dumped as a single text blob.

**Why:** So multi-item artifacts stay scannable instead of an unreadable wall of text.

**Activity:** Inspect one item's journey - Understand a specific item end-to-end - its artifacts, child steps, and logs - to see what happened or why it's stuck.

**Step:** View an artifact

**Status:** ready

### Acceptance Criteria

- Given an artifact declares kind `list`, when I select it with Enter or →, then it displays as its own scrollable list rather than raw text.
- Given the list has more items than fit on screen, when I scroll, then I can reach every item.

### Context

The live `Artifact` record (`lightcycle/domain/work/artifact.py`) is still `(type, value, label)` today - it has no `kind` field, so nothing in the engine can yet declare an artifact `list`. That field only exists as Change 1 in the TUI architecture doc, scoped there as part of this design's delivery rather than a separate prerequisite story, and it isn't landed yet. Kind is also never defaulted to `list` from any existing artifact `type` - it's only ever set by explicit declaration at attach time - so even once the field lands, there is no producer that naturally creates one; building and verifying this story means manually attaching a synthetic list-kind artifact to a node rather than exercising a real workflow path.
