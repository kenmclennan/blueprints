## Return to the list without losing position

**Who:** Operator

**What:** Closing the focused view returns to the priority list at the same scroll/selection position.

**Why:** So I can keep scanning without re-finding my place.

**Activity:** Inspect one item's journey - Understand a specific item end-to-end - its artifacts, child steps, and logs - to see what happened or why it's stuck.

**Step:** Find the item

**Status:** ready

### Acceptance Criteria

- Given I opened an item's detail view from a specific row, when I close it with Esc or ←, then the priority list reappears with that row still selected and the same scroll position.
- Given I scrolled or navigated within the detail view itself, when I return to the list, then the list's scroll position is unaffected by anything I did inside the detail view.

### References

- [wireframe-hub.html#active-log](../wireframes/wireframe-hub.md)

### Context

The priority list is live-updating and priority-sorted, not a static snapshot, and a sibling story - "Keep my selection on an item as it moves" - already owns what happens when the selected item changes bucket or position while its detail view is open, tracking the selection by item identity rather than by row index. This story is the return trip only: land the list on wherever that identity-tracked selection currently sits and restore the surrounding scroll, not re-derive what "same position" means against a list that may have reordered while the row was open.
