## Select an artifact to open it

**Who:** Operator

**What:** Arrow keys move through the artifact list; selecting one opens it.

**Why:** Consistent navigation with the tree and the priority list, not a one-off pattern.

**Activity:** Inspect one item's journey - Understand a specific item end-to-end - its artifacts, child steps, and logs - to see what happened or why it's stuck.

**Step:** Explore the artifacts on a node

**Status:** ready

### Acceptance Criteria

- Given the artifact list has more than one entry, when I press up/down, then the selection moves accordingly.
- Given an artifact is selected, when I confirm the selection with Enter or →, then it opens in the viewer appropriate for its type.

### References

- [wireframe-hub.html#needs-attention-human](../wireframes/wireframe-hub.md)

### Context

"Opens in the viewer appropriate for its type" is a hand-off, not a mapping this story owns. The type shown in the list (spec, branch, pr, brief, repo - per "See the artifacts attached to a node") is a free-form display label; which viewer actually opens is decided by kind (text, url, filepath, list), already fully specified by the four stories under the "View an artifact" step. Confirming a selection just routes into that existing kind-based dispatch - this story doesn't need its own type-to-viewer table, and a builder shouldn't build one here.
