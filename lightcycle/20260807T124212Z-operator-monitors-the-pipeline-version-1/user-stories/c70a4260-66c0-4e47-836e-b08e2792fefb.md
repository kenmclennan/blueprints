## Open a file-path artifact in its application

**Who:** Operator

**What:** A file-path artifact opens via whatever the OS already handles that file type with.

**Why:** So I use the right tool for it rather than a cramped in-terminal view.

**Activity:** Inspect one item's journey - Understand a specific item end-to-end - its artifacts, child steps, and logs - to see what happened or why it's stuck.

**Step:** View an artifact

**Status:** ready

### Acceptance Criteria

- Given an artifact declares kind `filepath`, when I select it with Enter or →, then it opens via the OS's default handler for that file type.
- Given the file no longer exists at that path, when I select it, then I see a clear message rather than a silent failure or crash.
- Given the file opens successfully, when that happens, then the TUI shows a brief confirmation toast and returns to the artifact list - there's no separate viewer screen to sit in, since the external application has taken over.
