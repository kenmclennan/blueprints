## See the artifacts attached to a node

**Who:** Operator

**What:** The current node's artifacts are listed, each labeled by type.

**Why:** So I know what's available before opening anything.

**Activity:** Inspect one item's journey - Understand a specific item end-to-end - its artifacts, child steps, and logs - to see what happened or why it's stuck.

**Step:** Explore the artifacts on a node

**Status:** ready

### Acceptance Criteria

- Given a node has one or more non-internal artifacts, when I open its artifact list, then each is shown labeled by its type (e.g. spec, branch, pr, brief).
- Given the artifact list is open, when I look at it, then only non-internal artifacts appear - internal bookkeeping types are never shown, consistent with the tree's content indicator.
- Given a node has no viewable artifacts, when I open its Artifacts tab, then a calm message is shown in place of the list, not a blank area.
- Given any node, whether or not it has viewable artifacts, when its hub is open, then the Artifacts tab is always present, so the Hierarchy/Log/Artifacts cycle is the same three tabs on every node.

### Context

The Artifacts tab is always offered, even when there is nothing to show. An earlier draft withheld the tab when a node had no viewable artifacts, which contradicted two other stories at once: "Land on the tab that matches the item's status" sends a done node to Artifacts, and "Cycle tabs with [ and ]" defines a fixed three-tab cycle. A done node whose only artifacts are internal satisfied all three antecedents and had nowhere valid to land. Since internal bookkeeping artifacts are the common case on steps, this was not an edge case. Resolved in favour of an empty state, matching the pattern already used for an empty priority list and an empty backlog, which also keeps the navigation contract identical on every node.
