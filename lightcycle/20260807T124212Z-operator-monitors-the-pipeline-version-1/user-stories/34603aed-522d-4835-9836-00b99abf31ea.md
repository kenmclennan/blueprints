## See whether the pool is running

**Who:** Operator

**What:** A footer status bar, visible on every screen, shows whether `lc start`'s pool is currently active.

**Why:** So I always know if my work will actually process, without checking a separate terminal or navigating anywhere.

**Activity:** Get oriented on the pipeline - See the whole pipeline at a glance - what's active, blocked, waiting on me, and queued - the moment it changes, as long as the dashboard is running.

**Step:** Launch the dashboard

**Status:** ready

### Acceptance Criteria

- Given `lc start` is running, when I look at the footer, then it shows a clear 'pool running' indicator.
- Given `lc start` is not running, when I look at the footer, then it shows a clear 'pool not running' indicator, never blank.
- Given the pool's running state changes while the dashboard is open, when that happens, then the footer updates without a manual refresh.

### Context

The pool's running state has no read-only accessor today. `lc start` determines it by calling `AcquireRunLockUseCase` (`lightcycle/application/pool/run_lock.py`), which attempts to actually claim `.lc-run.pid` in the data root via the file mechanics in `lightcycle/adapters/lock.py` - when no pool is running, that call succeeds and takes the lock itself. Wiring this footer indicator to that use case would violate the TUI's own "reads only, never writes" principle - whichever surface asks the question first when the pool is down would seize the lock and then block the real `lc start` from acquiring it. The read this story needs is the non-mutating half only - read the pid from `.lc-run.pid` and test liveness with the existing `pid_alive` check (`lightcycle/adapters/workers.py`) - exposed as a new read-only use case, not a reuse of the acquire path. This falls under the architecture doc's Change 4 (read-model gaps in the engine that are part of this design's delivery) but sits in `application/pool/`, not `application/work/` where that section's examples live, so it's easy to miss when scoping the work.
