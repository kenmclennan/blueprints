## See a contextual shortcut bar in the footer

**Who:** Operator

**What:** The footer shows the keyboard shortcuts actually available on the current screen, alongside the pool/version/upgrade status.

**Why:** So I don't have to memorise every key up front - the screen itself tells me what's live.

**Activity:** Get oriented on the pipeline - See the whole pipeline at a glance - what's active, blocked, waiting on me, and queued - the moment it changes, as long as the dashboard is running.

**Step:** Launch the dashboard

**Status:** ready

### Acceptance Criteria

- Given any screen, when I look at the footer, then it lists only the shortcuts relevant to that screen (e.g. 'a artifacts / l log' shows only in the tree).
- Given the screen changes, when that happens, then the footer's shortcut list updates to match.

### Context

A fixed, always-the-same shortcut bar would either have to show every key from every screen at once (cluttered, mostly irrelevant on any single screen) or a curated subset (misleading - the operator can't trust it's complete). Contextual solves both at once: whatever's shown is always exactly what works right now, nothing more and nothing missing.

Both wireframes show the shortcut list contracting within a single screen, not just switching wholesale between screens: the Backlog's empty state drops from the normal six shortcuts down to just tab and q, its empty-filtered state brings f back (filtering could still surface something), and the Priority List's empty state also drops to just tab and q. So the footer's contents have to track which actions are actually valid given the current data state, not a static per-screen shortcut list keyed only to which screen is active. Separately, when the Backlog's filter picker is open, the main footer's shortcut line stays exactly as it is for the underlying screen - the picker shows its own move/apply/cancel hints inside the overlay itself rather than replacing the persistent footer.
