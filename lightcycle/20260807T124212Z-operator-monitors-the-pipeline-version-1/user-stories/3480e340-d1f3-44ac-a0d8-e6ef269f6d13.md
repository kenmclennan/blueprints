## Cycle tabs with [ and ]

**Who:** Operator

**What:** Pressing ] moves to the next tab (Hierarchy → Log → Artifacts → Hierarchy); [ moves to the previous one. Tab keeps its own separate meaning (jump to Backlog) even while a node is open.

**Why:** So I can reach any tab in at most two presses without it colliding with Tab's global meaning.

**Activity:** Inspect one item's journey - Understand a specific item end-to-end - its artifacts, child steps, and logs - to see what happened or why it's stuck.

**Step:** Find the item

**Status:** ready

### Acceptance Criteria

- Given a node's hub is open, when I press ], then the next tab in the Hierarchy → Log → Artifacts cycle becomes active.
- Given a node's hub is open, when I press [, then the previous tab in that cycle becomes active.
- Given a node's hub is open, on any tab, when I press Tab, then I jump straight to Backlog (or Current work), same as everywhere else - it never gets reinterpreted as a tab-cycle key.
