## Return to the backlog without losing position

**Who:** Operator

**What:** Leaving a backlog item's tree view returns to the backlog at the same position.

**Why:** Same back-navigation contract as everywhere else.

**Activity:** See what's coming next - Know what's waiting in the backlog so nothing surprises me.

**Step:** See the todo backlog

**Status:** ready

### Acceptance Criteria

- Given I opened a backlog item's hub, when I close it with Esc or ←, then the backlog reappears at the same scroll/selection position.

### References

- [wireframe-backlog.html#normal](../wireframes/wireframe-backlog.md)

### Context

The backlog is a live, polled screen, not a static list - the same 10-second poll/diff loop described in tui-architecture.md's "Staying live" section governs it, same as the Priority List. So "same position" can't be a raw saved row index: the backlog's contents can shift while the operator is away in a backlog item's hub - most directly, the very item just opened could get activated and drop out of the backlog before Esc/← returns - so this relies on the same identity-based re-association the diff step already provides for the Priority List's selection-follows-item behaviour, not a separate position snapshot.
