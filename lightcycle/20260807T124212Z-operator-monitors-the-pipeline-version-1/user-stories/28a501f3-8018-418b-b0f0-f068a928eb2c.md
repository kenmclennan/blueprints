## See the live log tail as it's written

**Who:** Operator

**What:** New lines appear in place as the worker writes them, without manual refresh.

**Why:** To watch progress in real time.

**Activity:** Inspect one item's journey - Understand a specific item end-to-end - its artifacts, child steps, and logs - to see what happened or why it's stuck.

**Step:** Stream the current step's live log

**Status:** ready

### Acceptance Criteria

- Given the current step is being performed by a worker, when I open its live log, then new lines appear as they're written, without manual refresh.
- Given the live log is open and following the tail, when a new line arrives, then the view auto-scrolls to keep it visible.

### References

- [Live tail is implemented as direct file-offset tailing, independent of the 10s poll loop.](../architecture/tui-architecture.md)
- [wireframe-hub.html#active-log - LC-143.3 live tail example](../wireframes/wireframe-hub.md)

### Context

The acceptance criteria only cover the log while the step is still running - neither names what happens when the step being watched finishes while the log stays open. The same wireframe file this story cites (wireframe-hub.html) has a second state for exactly that moment, id="log-finished", not the id="active-log" anchor the reference note points to: the last real log lines are followed by a "step finished" marker and the cursor/now-line highlighting drops away. The architecture doc corroborates the mechanism behind that transition - the Log tab is "fed by the file-tailing loop... when live, or a static read of the past log when the step is done" - so this story's live-tailing behavior has to detect that handoff and stop tailing once the step completes, not just render new lines while it runs.
