## Return to the node without losing position

**Who:** Operator

**What:** Leaving the live log view returns to the node detail at the same position.

**Why:** Same back-navigation contract as everywhere else.

**Activity:** Inspect one item's journey - Understand a specific item end-to-end - its artifacts, child steps, and logs - to see what happened or why it's stuck.

**Step:** Stream the current step's live log

**Status:** ready

### Acceptance Criteria

- Given I opened the live log from a node's hub view, when I close it with Esc or ←, then the hub view reappears as it was.

### References

- [wireframe-hub.html#active-log](../wireframes/wireframe-hub.md)

### Context

The wireframe's "active-log" state is a contextual landing, not a two-step hub-then-log flow: opening an active item's node lands directly on the Log tab (the state is labelled "Active item... lands on Log"), so for the case that actually motivates this step there's no separate hub screen shown before the log appears - the log tab is the first thing rendered. Esc/← is a single, uniform back action shown identically in every wireframe state regardless of which tab is active, distinct from the [/] tab-cycle keys - so "returning to the hub view" here means exiting the node back to whatever screen it was opened from, at that screen's prior position, not stepping back to a previously-active tab within the same hub.
