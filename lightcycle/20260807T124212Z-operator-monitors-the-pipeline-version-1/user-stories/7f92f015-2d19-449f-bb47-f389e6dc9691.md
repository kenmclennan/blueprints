## Explore a backlog item's context in the hierarchy

**Who:** Operator

**What:** Selecting a backlog entry opens its hub, landing on the Hierarchy tab, showing its place in the tree.

**Why:** Consistent with how any node - active, done, or backlog - gets explored.

**Activity:** See what's coming next - Know what's waiting in the backlog so nothing surprises me.

**Step:** See the todo backlog

**Status:** ready

### Acceptance Criteria

- Given a backlog item is selected, when I open it with Enter or →, then its hub opens, landing on the Hierarchy tab, showing its place in the tree.

### References

- [wireframe-backlog.html#normal](../wireframes/wireframe-backlog.md)

### Context

A backlogged item has no step children by construction - `roll_up` over an empty child list resolves to `BACKLOGGED` (domain/work/rollup.py), and steps are only filed at activation (application/work/activate_item.py's `file_step` call, gated on `node.state != State.BACKLOGGED`). So the Hierarchy tab this story lands on is never the multi-row tree every cited state in wireframe-hub.html shows - it renders the item alone, with a theme ancestor above it only if one was already assigned before activation (application/work/backlog.py groups backlog rows by that same pre-existing `theme` field), and nothing beneath it.
