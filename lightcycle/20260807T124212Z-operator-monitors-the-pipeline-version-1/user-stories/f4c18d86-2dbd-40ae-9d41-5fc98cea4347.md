## Keep my selection on an item as it moves

**Who:** Operator

**What:** If the selected item changes state and moves position in the sorted list, the selection follows it rather than staying on whatever row is now in that slot.

**Why:** So live re-sorting doesn't yank my attention onto something I wasn't looking at.

**Activity:** Get oriented on the pipeline - See the whole pipeline at a glance - what's active, blocked, waiting on me, and queued - the moment it changes, as long as the dashboard is running.

**Step:** Review current work status

**Status:** ready

### Acceptance Criteria

- Given I have an item selected, when its state changes and it moves position in the sorted list, then my selection follows it to its new position.
- Given my selected item leaves the list entirely (e.g. becomes done), when that happens, then selection falls to the nearest remaining row rather than an empty selection.

### References

- ["Staying live" section explains how this falls out of the diff-based polling model directly.](../architecture/tui-architecture.md)
- [wireframe-priority-list.html#normal](../wireframes/wireframe-priority-list.md)

### Context

The cited "Staying live" passage grounds AC-1 directly - the diff step re-associates the tracked item by identity to its new row on every poll, so re-sorting alone never disturbs the selection. It doesn't cover AC-2: once the selected item's identity is missing from a poll's rows entirely, identity-based re-association has nothing left to match against, so the "nearest remaining row" fallback needs the item's last-known position from the prior render, not just its id - a second piece of state the diff step as described doesn't carry.
