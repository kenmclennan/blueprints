## See which engine version is running

**Who:** Operator

**What:** The footer status bar shows the installed lightcycle version at all times.

**Why:** So I know what I'm running when comparing behaviour or filing an issue, without leaving whatever I'm looking at.

**Activity:** Get oriented on the pipeline - See the whole pipeline at a glance - what's active, blocked, waiting on me, and queued - the moment it changes, as long as the dashboard is running.

**Step:** Launch the dashboard

**Status:** ready

### Acceptance Criteria

- Given the dashboard is open, when I look at the footer, then the installed lightcycle version is always shown (e.g. 'v0.42.1').
- Given lightcycle's version changes (e.g. after an upgrade and restart), when I next open the dashboard, then the footer reflects the new version, not a stale one.

### Context

The installed version is a static string - `lightcycle.__version__` in `lightcycle/__init__.py`, the same value `cli.py` imports for `lc version` - fixed for the life of the process. It has no row in store.db and needs no read-only use case or wiring into the footer's 10-second poll loop that drives the pool and claude-availability indicators; only a restart changes it, which is exactly what AC-2 already describes. The wireframes render this string on the same footer line as the "⬆ vX.Y.Z available" indicator, but that indicator belongs to the sibling story "See when a newer version is available," which checks a remote source through `application/setup/upgrade.py` - this story's scope stops at the plain installed-version string.
