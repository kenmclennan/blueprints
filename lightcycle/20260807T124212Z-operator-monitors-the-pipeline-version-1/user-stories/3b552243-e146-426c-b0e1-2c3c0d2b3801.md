## See the current node highlighted in the hierarchy

**Who:** Operator

**What:** Whichever node the hub is open for is highlighted in the Hierarchy tab, wherever it falls in the tree - not assumed to be the top row.

**Why:** So I always know where I am, even when I've drilled several levels deep.

**Activity:** Inspect one item's journey - Understand a specific item end-to-end - its artifacts, child steps, and logs - to see what happened or why it's stuck.

**Step:** Explore the hierarchy

**Status:** ready

### Acceptance Criteria

- Given the current node is a root item or theme with no parent, when I view the Hierarchy tab, then it's highlighted at the top row.
- Given the current node is nested under a theme and/or a parent item, when I view the Hierarchy tab, then it's highlighted at its actual depth, not the top row.

### Context

The tree this story highlights against is bounded, not open-ended: a node's parent expresses exactly one chain, theme > item > step, so "actual depth" only ever resolves to one of three positions - a themeless root or theme at the top row, an item nested one level under a theme, or a step nested one level under an item. There's no deeper recursion to account for, and ids mirror the same bound (LC-3 theme, LC-3.1 item, LC-3.1.1 step).
