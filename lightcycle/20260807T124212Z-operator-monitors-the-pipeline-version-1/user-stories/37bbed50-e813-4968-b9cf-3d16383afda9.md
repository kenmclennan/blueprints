## Follow a URL artifact

**Who:** Operator

**What:** A URL artifact (e.g. a PR link) opens in the default browser.

**Why:** So I can jump straight to it on GitHub.

**Activity:** Inspect one item's journey - Understand a specific item end-to-end - its artifacts, child steps, and logs - to see what happened or why it's stuck.

**Step:** View an artifact

**Status:** ready

### Acceptance Criteria

- Given an artifact declares kind `url`, when I select it with Enter or →, then it opens in the system's default browser.
- Given the URL fails to open (e.g. no browser available), when that happens, then I see a clear message rather than a silent failure.
- Given the URL opens successfully, when that happens, then the TUI shows a brief confirmation toast and returns to the artifact list - there's no separate viewer screen to sit in, since the browser has taken over.

### Context

The `kind` field this story's Given clause turns on doesn't exist on the engine's Artifact record yet - `lightcycle/domain/work/artifact.py` today defines only `type`, `value`, and `label`. Adding `kind` (and its `pr` → `url` default) is Change 1 in the TUI architecture doc, and that doc is explicit these engine changes belong to this design's delivery, not a prerequisite already handled elsewhere - no story may treat them as filed separately. So this story's scope includes making `kind` real on the Artifact record and its persistence, not just wiring `webbrowser.open()` on the assumption that `kind` is already there.
